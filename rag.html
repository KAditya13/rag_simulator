Step 1 · Document Chunking
i
PENDING
Large documents are split into smaller, overlapping chunks. Each chunk is ~200 tokens. Overlapping prevents losing context at boundaries.
🔢
Step 2 · Generating Embeddings
i
PENDING
An embedding model converts each chunk into a dense vector of numbers. Semantically similar text has vectors that are "close" in vector space.
🗄️
Step 3 · Vector Database Storage
i
PENDING
Embeddings are indexed in a vector database. Each cell below represents a stored vector. The DB is now ready for similarity queries.
02
QUERY PHASE
real-time · per query · retrieval + generation
🔍
Step 4 · Embed the Query
i
PENDING
The user's query is embedded with the same model used during indexing. This query vector is now ready to search the database.
—
📐
Step 5 · Cosine Similarity Search
i
PENDING
The query vector is compared to every stored vector using cosine similarity. The top-K most similar chunks are retrieved as candidates.
🏆
Step 6 · Reranking
i
PENDING
A cross-encoder model reads the query + each chunk together. It produces a more accurate relevance score than embedding similarity alone, reordering the chunks.
🤖
Step 7 · LLM Generation
i
PENDING
Top chunks are injected into the LLM prompt as context. The LLM generates an answer using ONLY this context — grounding the response and reducing hallucination.
